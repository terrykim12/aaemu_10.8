Date: 2026-08-31

## Evidence vocabulary

- **CONFIRMED**: directly established by the supplied/public source or by a deterministic local check.
- **HIGH CONFIDENCE**: strongly constrained by independent source facts, but not observed in the target client at runtime.
- **HYPOTHESIS**: plausible and source-supported, but not yet tied to the reported failure.
- **UNKNOWN**: the required target-client evidence was unavailable.

No r651723 client binary, packet capture, server database/configuration, current modified AAEmu branch, or running client/server process was supplied. The exact r651723 dump contains game scripts, not packet metadata or client reader disassembly. Consequently, this report distinguishes an internal serializer defect from claims that would require client/runtime evidence.

## 1. Executive summary

The first source-proven world-entry serializer failure is the shared 10.x position codec. The official 10.8 port changed `PacketStream.ReadPosition()` to consume 11 bytes, but left both `Helpers.ConvertPosition(float,float,float)` and `Helpers.ConvertPosition(byte[])` on the old 9-byte layout. `SCUnitStatePacket` calls `WritePosition` before scale, level, model, equipment, appearance, HP/MP, abilities, and buffs. It therefore emitted two fewer bytes than the server's own 10.8 reader contract and shifted every following field two bytes earlier.

- Classification: **CONFIRMED protocol implementation mismatch**; **HIGH CONFIDENCE** target-client mismatch.
- First affected operation in the local-player `SCUnitState` body: `WritePosition` at symbolic offset `0x14 + N + O`, where `N` and `O` are the UTF-8 byte lengths of character name and owner name.
- Patch: make both directions use the capture-backed 11-byte 10.x position representation and add a round-trip unit test.
- Not established: the exact first byte at which the r651723 client reader rejects `SCCharacterState` or `SCUnitState`. This needs r651723 disassembly, a read trace, or a raw capture.
- Stabilization result: **not verified**. Build restore and runtime testing are environment-blocked, so 5–10 clean entries, OOM/CTD elimination, movement, AOI, HUD, and relogin remain unproven.

The official 10.8 commit explicitly claims login/lobby only. Its world-entry serializers remain on an older lineage while the modern 10.0 branch has substantially different `SCCharacterState` and `SCUnitState` layouts. Those differences are an evidence map, not permission to transplant 10.0 fields into 10.8.

## 7. Confirmed mismatches and state hazards

1. **CONFIRMED:** 10.8 `ReadPosition` consumes 11 bytes while the writer/decoder helpers used the 9-byte layout. This affects `SCUnitState` and every other `WritePosition` caller. Patched.
2. **CONFIRMED:** the official 10.8 port updates the reader but leaves major world-entry serializers on the old lineage; its stated support ends at lobby. Individual target-field mismatches remain **UNKNOWN**.
3. **CONFIRMED:** two non-placeholder r651713 inbound `(level,opcode)` registrations silently overwrite earlier handlers, plus `0xFFF` placeholder collisions. No evidence ties these keys to world entry.
4. **CONFIRMED:** graceful `LeaveWorldTask` deletes the character and then `SaveAndRemoveFromWorld` deletes it again.
5. **CONFIRMED:** abrupt `GameConnection.OnDisconnect` saves/removes the character but does not explicitly set `IsOnline = false`, null the character connection/reference, clear subscriber lists, or release its object id in the inspected path.
6. **CONFIRMED:** static `Character.UsedCharacterObjIds` persists for process lifetime and intentionally reuses recorded object ids across reconnects.
7. **HYPOTHESIS:** items, appearance, skills, buffs, event subscriptions, and incomplete disconnect cleanup can make payload size/order or object state differ between entries. A successful/failed trace pair is required to connect any one of them to the symptom.
8. **UNKNOWN:** the OOM/CTD's first bad count. No crash dump, allocation stack, client reader trace, or packet capture was supplied; therefore no count clamp was added.
